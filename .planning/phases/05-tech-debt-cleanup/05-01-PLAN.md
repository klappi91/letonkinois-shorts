**In `supabase/schema.sql`:**

The `videos` table has `prompt_version text` (line 22) which stores UUID strings referencing `prompt_versions.id`. This works via Postgres implicit cast but lacks referential integrity.

Make two changes:

1. Change the column type from `text` to `uuid` on line 22:
```sql
-- Before:
  prompt_version  text,
-- After:
  prompt_version  uuid references public.prompt_versions(id),
```

2. Add a comment above the column clarifying the FK (inline with the CREATE TABLE, not a separate ALTER TABLE — keeps the schema file as a single source of truth for fresh installs):

The full `videos` CREATE TABLE should become:
```sql
create table if not exists public.videos (
  id              uuid primary key default gen_random_uuid(),
  title           text not null,
  caption_de      text,
  caption_fr      text,
  hashtags        text[] default '{}',
  type            text not null check (type in ('showcase','before-after','how-to','seasonal','heritage','lifestyle')),
  duration        integer,
  pipeline        text,
  status          text not null default 'draft' check (status in ('draft','approved','rejected')),
  prompt_version  uuid references public.prompt_versions(id),
  video_url       text,
  products        text[] default '{}',
  created_at      timestamptz not null default now()
);
```

Note: This is a documentation-only change to `schema.sql` (the canonical schema for fresh installs). The live Supabase DB already has data with TEXT values that are valid UUIDs. The live migration (ALTER TABLE videos ALTER COLUMN prompt_version TYPE uuid USING prompt_version::uuid, then ADD CONSTRAINT) should be run separately via Supabase SQL Editor or MCP if the user wants to apply it to the live DB. Do NOT run migrations against the live DB in this task.

Also update the `Video` interface comment in the schema file header to reflect this is now a proper FK:
