  <files>.env.local, supabase/schema.sql</files>
  <action>
This is a human-action checkpoint. The user must perform the following steps manually because they require Supabase Dashboard access and credential retrieval that Claude cannot do.

**Step 1 — Create Supabase Project (if not already done):**
1. Go to https://supabase.com/dashboard
2. Create a new project (or use existing one for letonkinois-shorts)
3. Note the project URL and keys

**Step 2 — Run Schema SQL:**
1. Go to Supabase Dashboard → SQL Editor
2. Open `supabase/schema.sql` from this repo
3. Paste the entire contents and click "Run"
4. Verify: Go to Table Editor — you should see `videos`, `feedback`, `prompt_versions` tables
5. Verify: Click each table → "Policies" tab — you should see RLS enabled and policies listed

**Step 3 — Set Admin Role (per D-01, D-02):**
1. Go to Supabase Dashboard → Authentication → Users
2. Find Chris's user (or create one with email/password)
3. Click the user → Edit → Raw User Meta Data is NOT what we need
4. Instead, go to SQL Editor and run:
   ```sql
   UPDATE auth.users
   SET raw_app_meta_data = raw_app_meta_data || '{"role": "admin"}'::jsonb
   WHERE email = 'YOUR_ADMIN_EMAIL';
   ```
   (Replace YOUR_ADMIN_EMAIL with the actual admin email)

**Step 4 — Provide Credentials:**
After completing the above, provide:
- `NEXT_PUBLIC_SUPABASE_URL` (from Dashboard → Settings → API → Project URL)
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` (from Dashboard → Settings → API → anon public key)
- `SUPABASE_SERVICE_ROLE_KEY` (from Dashboard → Settings → API → service_role secret key)
